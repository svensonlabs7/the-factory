# 74. WAF

Track: B. Security · Status: proven · Updated: 2026-10-18

## What it is
A web application firewall (WAF) inspects HTTP requests before they reach the app and blocks those that match attack patterns: SQL injection, XSS, path traversal, known scanners, abusive rates. Managed rulesets (OWASP Core Rule Set, Cloudflare's managed rules) use anomaly scoring: each matching rule adds points, and the request is blocked past a threshold. Higher "paranoia levels" add rules and catch more, at the cost of more false positives. A WAF is a mitigation layer in front of an app, never a substitute for fixing the app. Signatures miss attacks they were not written for, and they block legitimate requests that merely look like attacks.

## When it is worth it
It is worth it for public, unauthenticated, input-heavy surfaces (sign-up, search, forms, APIs used by anonymous clients), for a known vulnerability you cannot patch yet (a virtual patch), and for bot and scanner noise. Run it in log or simulate mode, tune it, then block. It adds little, and costs false positives, on endpoints where every request is already authenticated at the edge, or whose legitimate payloads are code-shaped text that trips SQL and XSS rules.

## How it fails
- **WAF instead of a fix:** the app stays vulnerable, and a rewritten payload (`'/**/OR/**/1=1--`, `$(curl ...)`) passes the signatures.
- **False positives on legitimate content:** a feature request that mentions `UNION ... SELECT`, `<script>`, `onclick=` or `../` is blocked, and the real user cannot do their job.
- **Blocking from day one, untuned:** an outage of legitimate traffic, after which someone disables the WAF entirely.
- **Inspecting the wrong layer:** encoded, compressed or JSON-nested payloads are not decoded the way the app decodes them, so the WAF and the app disagree.
- **Origin reachable around the WAF:** the app also answers on a direct IP or another hostname, and attackers skip the edge.

## Review checklist
- [ ] **Is the WAF a layer, not the fix?** · Applies when: the diff adds or relies on a WAF rule to address a vulnerability. · Block if: the underlying flaw in the app is not fixed or tracked.
- [ ] **Do the rules fit the endpoint's legitimate payloads?** · Applies when: the diff adds managed or custom WAF rules to an endpoint. · Block if: its legitimate traffic contains code, SQL, HTML or paths, and the rules were not tested against real examples of it.
- [ ] **Is a new rule rolled out in log mode first?** · Applies when: the diff adds a blocking WAF rule. · Block if: it goes straight to blocking without a log or simulate period, or a recorded test against real traffic.
- [ ] **Is the origin reachable only through the edge?** · Applies when: the diff exposes a service behind a WAF or CDN. · Block if: the origin also answers directly (public IP, another hostname, an open port).
