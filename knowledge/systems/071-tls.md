# 71. TLS

Track: B. Security · Status: proven · Updated: 2026-10-18

## What it is
Transport Layer Security (TLS) encrypts a connection and proves the server's identity with a certificate that a trusted authority signed for that hostname. Two halves must both hold.

**The server side** (RFC 9325, BCP 195):
- offers only TLS 1.2 and 1.3; TLS 1.0 and 1.1 MUST NOT be negotiated;
- uses forward-secret AEAD ciphers;
- holds a valid certificate whose SAN names the host;
- redirects HTTP to HTTPS, and sends HSTS so browsers never try plaintext again.

**The client side** verifies the chain and the hostname, and never turns verification off. A client that skips the check talks to anyone who intercepts the connection.

TLS can terminate at an edge (a CDN or tunnel), with the hop behind it either re-encrypted or kept on a trusted link such as loopback.

## When it is worth it
Every connection that leaves a machine needs it, internal ones included. That is table stakes at any scale. Managed edges (Cloudflare, load balancers) handle certificates and renewal, so the work is choosing their settings: minimum version and HSTS. Plain HTTP is acceptable only on loopback, or inside an already-encrypted tunnel. Certificate pinning, mutual TLS and running your own CA are worth it for high-value server-to-server links, and over-engineering for a single operator behind a managed edge.

## How it fails
- **Verification turned off:** `verify=False`, `curl -k` or `CERT_NONE` "to make it work" → an expired, self-signed or wrong-host certificate is accepted, and a man-in-the-middle reads and changes everything.
- **Old protocol versions left on:** TLS 1.0 and 1.1 with CBC/SHA-1 suites → weaker crypto and downgrade exposure, and they fail compliance baselines.
- **No HSTS:** a browser's first `http://` request, or a downgrade on a hostile network, travels in plaintext before the redirect.
- **Secrets sent before the redirect:** a client misconfigured with `http://` sends its auth headers and body in cleartext, and the server's 301 comes too late.
- **Expired certificate:** renewal fails silently → every client breaks at once.
- **Plaintext hop off-box:** TLS ends at a proxy and travels on unencrypted across a network.

## Review checklist
- [ ] **Is certificate verification left on?** · Applies when: the diff makes an HTTPS, TLS, git or package-manager call, or configures a client. · Block if: it disables verification (`verify=False`, `-k`, `CERT_NONE`, `check_hostname=False`, `NODE_TLS_REJECT_UNAUTHORIZED=0`, `sslVerify false`).
- [ ] **Does traffic leaving the machine use TLS?** · Applies when: the diff adds a URL, endpoint or connection to another host. · Block if: it uses `http://` or plaintext to anything other than loopback, or a hop inside an existing encrypted tunnel.
- [ ] **Does a new public endpoint set modern TLS and HSTS?** · Applies when: the diff exposes a new hostname or changes edge configuration that lives in the repo. · Block if: the configuration the diff itself controls allows TLS below 1.2, or omits HSTS for a browser-facing host it adds.
- [ ] **Do clients send secrets only over HTTPS?** · Applies when: the diff configures a client with credentials. · Block if: the endpoint URL could be `http://`.
